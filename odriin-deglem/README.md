# Өдрийн дэглэм · 51 дүгээр сургууль

Сурагч, багш, эцэг эх өдөр тутмын дэглэм, оноо, шагналаа хөтөлдөг веб систем. Frontend нь цэвэр HTML, CSS, JavaScript дээр бичигдсэн, build хэрэггүй. Нэвтрэлт болон өгөгдлийг Supabase (Auth + PostgreSQL + Row Level Security) хариуцна.

> **Supabase тохируулж дуустал сайт ажиллахгүй.** Тохиргоо дутуу үед сайт «Сервер тохируулаагүй байна» гэсэн дэлгэц харуулна. Ажиллаж байгаа мэт дүр эсгэхгүй.

---

## Тохируулах алхмууд

Эхний удаа 20–30 минут орно. Node.js 18 буюу түүнээс шинэ хувилбар хэрэгтэй (`node -v` командаар шалгана).

### 1. Supabase төсөл үүсгэх

1. https://supabase.com руу ороод нэвтэрнэ (GitHub эсвэл и-мэйлээр).
2. **New project** товчийг дарна.
3. **Name:** `odriin-deglem` (дурын нэр байж болно).
4. **Database Password:** хүчтэй нууц үг үүсгээд аюулгүй газар хадгална. Энэ апп-д шууд хэрэглэгдэхгүй ч төслийг удирдахад хэрэгтэй.
5. **Region:** Монголд хамгийн ойр нь **Northeast Asia (Tokyo)** эсвэл **Southeast Asia (Singapore)**.
6. **Create new project**-ийг дарж, 1–2 минут хүлээнэ.

### 2. Database үүсгэх (migration ажиллуулах)

1. Зүүн цэснээс **SQL Editor** → **New query**.
2. `supabase/migrations/0001_init.sql` файлын агуулгыг **бүтнээр нь** хуулж буулгана.
3. **Run** дарна. «Success. No rows returned» гарвал болсон.
4. **Table Editor** хэсэгт `profiles`, `tasks`, `daily_logs`, `rewards`, `reward_transactions`, `user_settings` зэрэг 13 хүснэгт гарсан байх ёстой.

Энэ migration-ийг нэг л удаа ажиллуулна. Дахин ажиллуулбал «already exists» алдаа гарна, энэ нь хэвийн бөгөөд өгөгдлийг эвдэхгүй.

### 3. Нээлттэй бүртгэлийг хаах

Аккаунтыг зөвхөн сургууль үүсгэнэ. Гадны хүн өөрөө бүртгүүлэх боломжийг хаана.

1. **Authentication** → **Sign In / Providers** (хуучин интерфэйст **Providers** → **Email**).
2. **Allow new users to sign up**-ийг **унтраана**.
3. **Save**.

Email provider өөрөө асаалттай үлдэнэ: нэвтрэлт и-мэйл болон нууц үгээр явагдана.

### 4. Түлхүүрүүдээ хуулах

**Project Settings** (араан дүрс) → **API** эсвэл **API Keys** хэсгээс:

| Supabase дээрх нэр | Хаана бичих | Нууц эсэх |
|---|---|---|
| Project URL | `SUPABASE_URL` | Нийтэд ил байж болно |
| `anon` `public` эсвэл **Publishable key** (`sb_publishable_…`) | `SUPABASE_ANON_KEY` | Нийтэд ил байж болно. Хамгаалалтыг RLS хийнэ |
| `service_role` эсвэл **Secret key** (`sb_secret_…`) | `SUPABASE_SERVICE_ROLE_KEY` | **Нууц.** Хэнд ч бүү өг, GitHub-д бүү оруул |

### 5. `.env.local` бөглөх

Төслийн хавтаст терминал нээгээд:

```bash
npm install
cp .env.local.example .env.local      # Windows: copy .env.local.example .env.local
```

`.env.local`-ийг нээж 4-р алхмын утгуудыг бичнэ:

```
SUPABASE_URL=https://abcdefghijklmnop.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOi...   (эсвэл sb_publishable_...)
USERNAME_DOMAIN=students.51.local
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...   (эсвэл sb_secret_...)
```

`.env.local` нь `.gitignore`-д орсон тул GitHub руу явахгүй.

Дараа нь:

```bash
npm run config
```

Энэ команд `public/config.js` файлыг үүсгэнэ. Тэр файлд зөвхөн URL болон anon түлхүүр бичигдэнэ. service_role түлхүүрийг андуурч anon-ы оронд бичвэл команд алдаа өгч зогсоно.

### 6. Аккаунт үүсгэх

`USERNAME_DOMAIN` тохируулсан тул сурагч и-мэйлгүйгээр нэвтрэх нэрээр (жишээ нь `bat`) орж болно. Багш, эцэг эхэд жинхэнэ и-мэйл хэрэглэхийг зөвлөж байна.

```bash
# Сурагч: аккаунт → ангийн мэдээлэл ба анхны төлөвлөгөө (18 даалгавар, хуваарь, 5 шагнал)
npm run admin -- user bat student "Бат-Эрдэнэ"
npm run admin -- student bat "3б анги"

# Багш
npm run admin -- user saraa@51.mn teacher "Сараа багш"
npm run admin -- link-teacher saraa@51.mn bat

# Эцэг эх
npm run admin -- user dulmaa@gmail.com guardian "Дулмаа"
npm run admin -- link-parent dulmaa@gmail.com bat

# Шалгах
npm run admin -- list
```

Нууц үг өгөөгүй бол скрипт түр нууц үг үүсгэж хэвлэнэ. Түүнийг хэрэглэгчид биечлэн өгнө. Нууц үг мартсан бол:

```bash
npm run admin -- password bat
```

### 7. Компьютер дээрээ ажиллуулах

```bash
npm start
```

Терминалд гарсан хаягийг (ихэвчлэн http://localhost:3000) хөтчөөр нээнэ.

### 8. Интернэтэд байршуулах (Netlify эсвэл Vercel)

Төслийг GitHub руу оруулна. `.env.local` болон `config.js` автоматаар орохгүй.

**Netlify:** Add new site → Import from GitHub → төслөө сонгоно. Build тохиргоо `netlify.toml`-оос уншигдана. **Site configuration → Environment variables** хэсэгт гурван утга нэмнэ:

```
SUPABASE_URL, SUPABASE_ANON_KEY, USERNAME_DOMAIN
```

**Vercel:** Add New → Project → төслөө сонгоно. `vercel.json` бэлэн байгаа. **Environment Variables**-д дээрх гурван утгыг нэмнэ.

> `SUPABASE_SERVICE_ROLE_KEY`-г Netlify эсвэл Vercel-д **бүү** нэм. Тэр түлхүүр зөвхөн админы скриптэд хэрэгтэй.

Байршуулсны дараа Supabase → **Authentication → URL Configuration → Site URL**-д сайтынхаа хаягийг бичнэ.

### 9. Жинхэнэ аккаунтаар шалгах

1. Сурагчаар нэвтэрнэ. Хоёр даалгавар тэмдэглэхэд ахиц болон оноо өснө. Тэмдэглэл, өдрийн бүртгэл бичээд хадгална.
2. Supabase → Table Editor → `task_completions` болон `daily_logs` хүснэгтэд мөр нэмэгдсэнийг шалгана.
3. Хуудсыг refresh хийнэ. Мэдээлэл хэвээр байх ёстой.
4. Өөр утас эсвэл компьютерээс ижил сурагчаар нэвтэрнэ. Ижил мэдээлэл харагдах ёстой.
5. «Шагнал» хэсгээс оноо хүрэх шагнал авна. Оноо хасагдсаныг шалгана.
6. Гараад багшаар нэвтэрнэ. Сурагчийн ахиц харагдана. Даалгавар засах, тэмдэглэл бичих, оноо тохируулахыг туршина.
7. Гараад эцэг эхээр нэвтэрнэ. Зөвхөн өөрийн хүүхэд харагдах ёстой. Гэрийн хуудсаа бөглөнө.
8. Сурагчийн нэвтрэх нэрээр «Багш» role сонгож нэвтэрч үзнэ. Татгалзах ёстой.

Дэлгэцийн хэрэглээг гараар оруулдаг. Сайт утас, компьютерийн хэрэглээг өөрөө хянадаггүй.

## Аюулгүй байдал

- **Role шалгалт.** Нэвтрэх үеийн role сонголт эрх олгодоггүй. Нэвтэрсний дараа `verify_login_role()` функцээр database дахь бодит эрхтэй харьцуулна. Таарахгүй бол шууд гаргана.
- **Role оноох.** Role-ийг `profiles.role` баганад хадгална. Хэрэглэгч энэ хүснэгтэд бичих эрхгүй. Зөвхөн админ (service role) онооно.
- **Row Level Security.** 13 хүснэгт бүгдэд идэвхтэй. Сурагч өөрийгөө, багш хариуцсан сурагчаа, эцэг эх өөрийн хүүхдээ л харна. URL эсвэл ID өөрчлөөд бусдын мэдээлэлд хандаж чадахгүй.
- **Оноо.** Оноог сервер тооцдог. Клиент оноо бичих эрхгүй. Шагнал авах (`redeem_reward`) болон оноо тохируулах (`adjust_points`) нь серверийн функцээр, түгжээтэй явагдана. Нэг даалгавар нэг өдөрт ганц мөртэй тул давхар оноо гарахгүй. Шагналд зарцуулсан оноотой даалгаврыг буцаах боломжгүй.
- **Түлхүүр.** Браузерт зөвхөн anon түлхүүр очно. service_role түлхүүр `.env.local`-д үлдэж, зөвхөн `scripts/admin.mjs` хэрэглэнэ.

## Тест

```bash
npm run test:rls   # 85 шалгалт: эрх, оноо, шагналыг жинхэнэ Postgres (PGlite) дээр
npm test           # 65 шалгалт: login, 3 dashboard, хадгалалт, алдаа, refresh, өөр төхөөрөмж, theme
```

`npm test` нь Supabase-ийг санах ойн дуурайлтаар орлуулж (`tests/mock-supabase.mjs`) апп-ын урсгалыг шалгадаг. Эрхийн жинхэнэ хамгаалалтыг `test:rls` шалгадаг. Supabase сервертэй бодитоор холбогдсон эсэхийг 9-р алхмаар шалгана.

## Database

| Хүснэгт | Агуулга |
|---|---|
| `profiles` | Хэрэглэгч, role, нэр |
| `student_profiles` | Анги, өдрийн зорилгын хувь, дэлгэцийн хязгаар |
| `student_teacher_assignments` | Багш ↔ сурагч |
| `parent_student_assignments` | Эцэг эх ↔ сурагч |
| `tasks` | Даалгавар (бүлэг, хугацаа, оноо) |
| `task_completions` | Даалгаврын өдөр тутмын төлөв ба авсан оноо |
| `daily_logs` | Өдөр бүрийн тэмдэглэл, дэлгэц, хөдөлгөөн, ариун цэвэр, нойр |
| `schedule_items` | Өдрийн хуваарь |
| `day_goals` | Өдрийн жижиг зорилго |
| `teacher_notes` | Багшийн тэмдэглэл (эцэг эхтэй хуваалцах эсэх) |
| `rewards` | Шагнал ба шаардлагатай оноо |
| `reward_transactions` | Шагнал авсан ба багшийн онооны тохируулгын түүх |
| `user_settings` | Хэрэглэгчийн тохиргоо (өдөр/шөнийн горим) |

Бүх хүснэгт `created_at`, `updated_at` талбартай. Өдөр тутмын бүртгэл (сурагч, огноо)-оор давтагдашгүй тул нэг өдөр нөгөөгөө дарахгүй.

## Мэдэгдэж буй хязгаарлалт

- **Supabase Storage** ашиглаагүй: одоогийн боломжууд зураг, файл хадгалах шаардлагагүй.
- **Админы вэб интерфэйс** байхгүй: аккаунтыг `npm run admin`-аар эсвэл Supabase Dashboard-аас үүсгэнэ.
- **Нууц үг сэргээх и-мэйл** оруулаагүй: сурагчид ихэвчлэн и-мэйлгүй тул нууц үгийг админ сольдог.
- **Синк.** Өөр төхөөрөмж дээр хийсэн өөрчлөлт нэвтрэх, refresh хийх эсвэл таб руу буцаж ирэх үед ачаалагдана. Хоёр дэлгэц зэрэг нээлттэй байхад шууд (realtime) шинэчлэгдэхгүй.
- Хуудас сүүлийн 60 хоногийн бүртгэлийг ачаална. Оноог бүх түүхээс тооцно.
